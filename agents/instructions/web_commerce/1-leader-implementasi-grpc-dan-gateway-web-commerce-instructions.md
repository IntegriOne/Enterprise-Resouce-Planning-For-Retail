## Task

Bangun satu server gRPC privat untuk channel/storefront, konten listing, profil buyer, cart, penawaran tersegel, submission checkout dan koordinasi sesudah pembelian. Sambungkan ke satu endpoint browser `/api/graphql`. Kerjakan dari baseline SQL hingga E2E. Untuk setiap aturan bisnis, buktikan pemilik keputusan, hak aktor, perubahan state dan perilaku saat panggilan ke pemilik gagal.

Baca [logika bisnis Web Commerce, khususnya bagian kedua §19–29](../../logic/web_commerce/logic.md) dan [DBML beserta implementation contract di bagian akhir](../../../backend/services/web_commerce/web_commerce.dbml). Gunakan [inventaris per operasi](../../grpc/web_commerce/1-inventaris-operasi-grpc-dan-graphql-web-commerce.md) sebagai daftar kerja. Di sana setiap Query dan Mutation mempunyai RPC usulan, aktor, input kunci, hasil dan aturan penerimaan. Sinkronkan perubahan nama atau keputusan owner di kedua sisi kontrak dan pada inventaris.

3. Bekerja sampai seluruh paket yang dapat dijalankan selesai; jangan berhenti setelah scaffolding, generator atau tes mock. F1 internal, F2 mandat pihak luar, F3 integrasi/analitik, F4 pembeli/tamu. Pengaktifan produksi mengikuti gate owner masing-masing.
4. Simpan matriks dan penjelasan detail operasi di `agents/grpc/web_commerce/{id}-{title}.md`, laporan aktual di `agents/e2e/web_commerce/{id}-{title}.md`, kebutuhan owner di `agents/notes/web_commerce/{id}-{title}.md`, dan konteks/riwayat menurut AGENTS.md. Untuk setiap kekurangan, cantumkan pemilik, data yang diperlukan, key, bukti yang dibalas, failure mode, operasi terdampak dan cara verifikasinya.
5. Tinjau diff, re-index graph, commit hanya pekerjaan sendiri di main dan laporkan SHA yang terverifikasi di remote, file, angka cakupan, bug/logika yang diperbaiki dan gate yang masih terbuka.
