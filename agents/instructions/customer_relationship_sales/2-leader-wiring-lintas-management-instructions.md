- **owner** — Developer CRM memimpin integrasi. Tiap developer owner menerbitkan fakta dari modulnya.
- **priority** — IAM/EF/HRM/PLM untuk internal, kemudian Commerce/OMS/Finance dan DRM/provider. Customer Service mengikuti kesiapan owner.
- **status** — SIAP DIKERJAKAN bersama instruksi 1 pada tahap yang relevan

### Penerbit dan penerima event

| Event usulan | Outbox → inbox | Kunci efek dan penggunaan |
| --- | --- | --- |
| SalesQuoteLinked / SalesOrderConfirmed / SalesOrderCancelled | Commerce → CRM dengan provenance OMS untuk order | Kombinasi producer + document/line + source version, nilai dan bukti dibekukan. Kendalikan konversi parsial. |
| SalesRelationshipLinked / SalesCreditCorrected | CRM → Commerce, konsumen performance berizin | Link UUID stabil, waktu berlaku, revisi credit dan digest. Pembaruan referensi balik tidak mengubah digest dokumen komersial. |
| CommercialSalePosted / CommercialCreditPosted | Finance → CRM | Posting/credit + original sale line. Backfill memakai mapping yang sama dan menjaga watermark. |
| ContactPermissionChanged | CRM → dispatcher dan konsumen terotorisasi | Token endpoint internal, purpose, scope, revision. Re-evaluate sebelum send, sebar data minimum ke audience sah. |
| RelationshipMessageReceived / MessageDeliveryObserved | Adapter → CRM | Account + event key dan message/thread ID. Simpan timestamp bukti dari provider tanpa memundurkan status. |
| SalesFollowUpDue | CRM → notifier privat bila tersedia | Task ID + revisi due + occurrence, pengingat usang diabaikan. |
| SupportHandoffRequested / SupportHandoffAcknowledged | CRM ↔ CS | Key stabil untuk satu permintaan. Owner ticket ref/versi/status pada respons. |

- file: Di CRM buat `domain/service/ports.go`, `infrastructure/integration/<owner>/client.go`, `infrastructure/inbox/processor.go`, `infrastructure/outbox/relay.go`, `transport/grpc/handler/integration_handler.go` dan registrasi di `cmd/wiring.go`. Pada owner lihat permintaan spesifik di tabel.
- function: Verifier sinkron dengan timeout, publisher dan consumer idempoten, Claim/Apply/Reconcile/DLQ, private handlers menurut katalog. Modelkan evidence sebagai ID owner + subjek + versi + digest + waktu yang berlaku.
- logic: Simpan command dan outbox sebelum efek remote. Gunakan claim pendek dengan lease/token, lepaskan transaksi sebelum panggilan jaringan, lalu finalisasi dengan CAS/fencing. Event lebih baru yang membutuhkan prasyarat diparkir. Simpan watermark terproses, revalidasi snapshot atau backfill saat ada gap. Untuk integrasi synchronous, batasi umur hasil verifikasi dan recheck sebelum state sensitif.
- error_handling: Duplicate + digest sama → hasil sama. Digest berbeda → konflik permanen dengan audit. Unknown/deadline → query status memakai key lama. Backoff terbatas + jitter, DLQ dan replay berizin yang menunjukkan source sequence.
- security: Allowlist producer per event/RPC dan arah. Verifikasi sertifikat workload serta scope bisnis/subject. Jangan meneruskan grant buatan client, payload bebas berisi PII, credential provider atau SQL lintas database.
- expected_result: Satu efek per fakta ekonomi/komunikasi, serta bukti bahwa kegagalan satu owner hanya menahan use case yang memerlukannya.
- testing: Validasi normal, mTLS salah, scope dan subject salah, replay, out-of-order, timeout sesudah owner commit, recovery sesudah restart worker, audit dan nilai persisten. Unit test gRPC berada di services. Untuk Gateway gunakan HTTPS dan role dari GraphQL IAM.

## Action

1. Verifikasi dial/client/cert dan policy untuk setiap pasangan. Pasangkan konfigurasi client dengan readiness capability. Hindari client stub yang melaporkan sukses.
2. Buktikan contoh lengkap sales B2B dari lead → opportunity → request quote → quote issued → OMS confirmed → credit frozen → Finance posted → achievement. Bandingkan net dan currency pada setiap langkah.
3. Buktikan opt-out sesudah queue dan lampiran revoked sebelum kirim. Uji dua salesperson di unit berbeda dan approver independen.
4. Jalankan skenario gagal dengan satu owner dimatikan, periksa visibility data dan backlog, lalu pulihkan dan buktikan hasil tepat satu kali. Lampirkan bukti HTTPS untuk user dan bukti mTLS untuk workload. Sertakan daftar operasi aktif, yang tertahan, owner, source SHA dan lokasi E2E.
