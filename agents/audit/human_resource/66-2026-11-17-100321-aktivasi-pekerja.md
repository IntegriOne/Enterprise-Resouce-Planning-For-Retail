# Audit aktivasi pekerja HRM

## Temuan dan perbaikan

Persetujuan penempatan mensyaratkan pekerja aktif, tetapi sebelumnya tidak ada command untuk mengubah `preboarding` menjadi `active`; tes integrasi mengubah status langsung lewat SQL. Kini `ActivateWorker` tersedia sebagai RPC privat dengan permission `human_resource.workers.activate` dan step-up. Command menolak actor workload, status selain `preboarding`, tanggal masuk/mulai layanan yang belum tiba, dan aktivasi ulang. Validator memeriksa kontrak `signed` yang efektif, referensi dokumen tanda tangan serta digest, kesamaan badan hukum, dan bukti Foundation. Semua perubahan worker dan outbox berada dalam satu transaksi; update status lewat CRUD tetap ditolak.

## Verifikasi

- `go fmt ./...`, `go vet ./...`, `go test -race ./...`: lulus.
- gRPC–PostgreSQL pada database `_test` sekali pakai dengan `-race`: lulus untuk penolakan tanpa kontrak, aktivasi dan retry.
- `docker compose build human-resource` dan `docker compose up -d --wait human-resource`: lulus, container healthy.

## Batas bukti

Tes positif memakai fixture kontrak bertanda tangan di database. Belum ada command penandatanganan atau verifikasi dokumen oleh DRM, dan verifier Foundation produksi masih nil. Aktivasi produksi tetap gagal tertutup hingga dependency owner tersebut tersedia; tes ini bukan bukti E2E IAM–Gateway–Foundation–DRM.
