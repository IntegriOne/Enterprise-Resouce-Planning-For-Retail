## Apa yang sudah dikerjakan

- **Audit ulang 17 November 2026 (audit nomor 12):** enam service/81 RPC, 16 tabel, wiring dan jalur domain–repository–service–handler dicocokkan lagi. `session.NewService` kini menolak outbox aktif tanpa transaktor; tes mock, format, vet, build dan race test lulus. Coverage statement empat lapisan 51,8%; bukan bukti E2E semua alur.
- **Grant scope eksternal 17 November 2026 (audit nomor 11):** assignment role pengguna/grup kini gagal tertutup dengan `Unavailable` untuk scope non-global/non-self sampai ada pembuktian objek dari owner. Tes domain, service, dan bufconn mengonfirmasi penolakan sebelum penulisan; kebutuhan kontrak tercatat pada `agents/notes/enterprise_foundation/1-iam.md`.
- **Hardening RBAC 17 November 2026 (audit nomor 10):** service role/group sekarang mewajibkan `SecurityRuntime` dan `OutboxCoord`; koordinator outbox gagal tertutup bila dependency internalnya tidak siap. Pencabutan assignment langsung/grup tidak dapat melewati resolusi subjek dan revisi akses. Tes PostgreSQL pada database disposable membuktikan kegagalan insert outbox me-rollback DELETE dan revisi, sedangkan jalur sukses menyimpan dua event. `go fmt`, `go vet`, `go build`, dan race test IAM lulus.
- **Audit ulang seluruh business flow 17 November 2026 (audit nomor 9):** enam kelompok/81 RPC dicocokkan dengan lapisan domain–repository–service–handler dan dibedakan dari pembuktian transaksi nyata. `go vet`, race test, dan pengukuran coverage gabungan lulus; coverage statement gabungan empat lapisan 51,1%. Audit ini tidak mengubah source IAM.
- **Audit menyeluruh lanjutan 17 November 2026 (audit nomor 8):** inventaris 16 tabel dan 81 RPC enam kelompok dicocokkan dengan lapisan domain–repository–service–handler. Bootstrap kini meneruskan kegagalan refresh snapshot, aktivasi akun, dan lookup UUID alih-alih melaporkan sukses; tiga tes injeksi gagal lulus. Go fmt/vet/build/race lulus. Bukti PostgreSQL/Redis dan temuan terbuka dibedakan secara eksplisit pada audit nomor 8.
- **Audit ulang seluruh enam domain IAM 17 November 2026 (audit nomor 6):** 81 RPC dan alur domain–repository–service–handler dicocokkan ulang. Repository sesi kini memeriksa idle/absolute expiry saat UPDATE aktivitas/MFA dan menjaga cap aktivitas monotonik; tes PostgreSQL terisolasi membuktikan kasus aktif, kedaluwarsa, dan permintaan lama. Go fmt/vet/race/build lulus. Batas bukti lintas domain tetap tercatat di audit nomor 6.
- **Audit ulang lintas lapisan 17 November 2026:** inventaris 16 tabel dan 81 RPC enam domain dicocokkan dengan service/repository, lalu bukti mock dipisahkan dari PostgreSQL/Redis nyata. Callback pascacommit pada savepoint gagal diperbaiki dan diuji. Tes migrasi dan live Redis yang destruktif kini hanya menerima database `iam_disposable_*_test` dengan opt-in. Migrasi serta alur bootstrap/login/outbox/outage/recovery lulus pada DB sementara dan Redis TLS; Go fmt/vet/race lulus. Detail dan insiden `iam_test` ada di audit IAM nomor 5.
- **Audit menyeluruh flow gRPC 17 November 2026:** 81 RPC pada User/Identity (20), Auth/MFA (12), Session (13), Role (15), Group (15), dan Permission (6) telah dicocokkan ke service, domain, dan repository; seluruh method RPC mempunyai eksekusi tes. Token verifikasi email kini terikat ke identitas email tepat; token tanpa target serta request untuk email yang sudah verified ditolak. Permintaan token mengirim email setelah transaksi. RPC self membutuhkan caller terautentikasi; `GetSessionCsrf` hanya menerima session ID caller. CreateRole RPC tidak dapat membuat role sistem; snapshot repository gagal tertutup jika recovery epoch tidak tersedia. `go fmt`, `go vet`, race test IAM, build/restart Docker IAM, dan matriks E2E Gateway Query/Mutation selain fixture permission resource lama lulus. Detail di audit IAM nomor 4.
- **Hardening IAM gRPC 17 November 2026:** kode permission baru wajib sejalan dengan `resource` namespaced dan `action`; bootstrap memperbaiki metadata katalog lama dan menolak drift `is_sensitive`; permission yang masih terpasang pada role tidak dapat dihapus. `assigned_by` dan `group_members.added_by` berasal dari caller internal terverifikasi, bukan payload. Penulisan outbox sesi gagal tertutup; pemilik sesi nonaktif tidak lolos authenticate/CSRF/MFA; kegagalan recovery epoch menghalangi refresh snapshot. RPC `IssueSession` hanya untuk caller terautentikasi dengan `user_id` sama dan tanpa klaim MFA; `MarkSessionMfaVerified` ditolak dan didepresiasi, gunakan `AuthService.VerifySessionMfa`. HMAC internal wajib pada runtime development/production.
- `go fmt ./...`, `go vet ./...`, dan `go test -race -count=1 ./...` lulus pada modul IAM; `go generate ./...` kontrak serta `docker compose build iam` lulus. Container IAM development sudah direstart sendiri dan sehat; smoke live membuktikan gRPC health `SERVING`, RPC bisnis tanpa HMAC mendapat `Unauthenticated`, dan `/api/graphql` tetap merespons query publik. E2E `TestMutationUserLogin` lulus; matriks Query/Mutation lulus bila `TestQueryPermissions` dikecualikan. - Enam RPC list relasi belum memakai limit/offset; kontrak dan query repository perlu pagination.
- Tes PostgreSQL terisolasi sudah ada untuk repository sesi, tetapi tes gRPC→PostgreSQL bagi seluruh alur auth/role/group belum lengkap.

Pengiriman email belum memakai outbox tahan gangguan. Cakupan historis statement handler 69,4% dan service 62,3%; cabang fault injection repository belum lengkap.
- Tes E2E `TestQueryPermissions` pada Gateway perlu menyelaraskan filter resource menjadi `iam.users`; audit data permission lama dalam database development masih perlu dilakukan.
- Konfigurasi deployment produksi (`APP_ENV=production` dan mTLS internal gRPC) pada lingkungan staging/production nyata.
- Integrasi layanan domain hilir lain (Enterprise Foundation, HRM, Procurement, Commerce) terhadap event/lookup IAM mengikuti fase berikutnya.
